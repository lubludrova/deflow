# Independent implementation and reproducibility review

Date: 2026-11-11. Review of revision2 package and local original docking engine. Read-only inspection of code and raw diagnostic JSONs. No training, GPU work, remote operations, or existing source edits performed. This report does not claim newly executed tests.

## Verdict

**Do not restart with the current revision2 entrypoints.** Uniform strict FP32 is not implemented or recorded. A fresh, separately versioned package/engine snapshot with an explicit numerical policy and bounded preflight is required. The sequential Newton algorithm can provisionally remain byte-for-byte unchanged. The evidence supports fixing execution precision before redesigning Newton. It does not establish universal convergence, exact finite-sampler likelihood, full-training stability, or the predicted campaign wall time.

Scope remains the same 12 fresh runs, seeds 1/2/3, 200k transitions, four declared solver arms. Preserve old high/TF32 artifacts as a separate stopped campaign. No resume or mixed-policy aggregation.

## P0: training overrides precision and other entrypoints do not enforce parity

`src/docking_full/sac_anderson_flow.py:1007-1009` unconditionally sets CUDA matmul TF32 and cuDNN TF32 true, followed by matmul precision `high`. A policy set before `engine.main(args)` in `run_docking.py` is overwritten. `evaluate.py`, `audit.py`, and `prepare_inputs.py` never establish numerical policy. In a fresh process their policy can differ from training, and in a reused process it can depend on earlier calls. `.float()` is not a prohibition on TF32. Current manifests record Torch and source hashes but not effective precision.

Preferred transparent fix: create a NEW frozen engine snapshot with one explicit Args precision-policy field, defaulting to historical high/TF32 behavior, and apply it at the existing three-assignment override point. The restart package must pass strict FP32 and the branch must set false, false, and `highest`. This makes the intended policy part of checkpoint args and avoids implicitly changing unrelated callers. Explicitly review this diff before regenerating the expected engine manifest. A campaign-only frozen engine with those three assignments directly changed is smaller but less reusable. Do not modify the historical engine snapshot that previous results depend on. Use one small policy helper in the new package to set and assert the same three settings in evaluation, audit, and reconstructed-input preparation, and assert them at the first actual actor invocation after engine initialization. Alternatively apply policy in the instrumented actor constructor after native engine setup, before actor initialization and subsequent critic construction. That alternative retains the original engine hashes but is less obvious and requires a test proving initialization order. Do not patch global Torch setters to no-op or rely solely on shell environment variables.

The policy is process-wide and must cover actor field calls, Jacobians, critic training, native dense backward, density, telemetry recomputation, and evaluation. Do not scope strict settings to the Newton function alone. Record requested policy and actual getter values, float/input/model dtypes, CUDA/cuDNN/Torch versions, physical GPU mapping, and relevant backend environment overrides. An initial plan manifest is not evidence of runtime policy. Write a runtime record after native initialization and include it in capsules and evaluation/audit output. Assert again at capsule boundaries and evaluation/audit entry. A mismatch should fail visibly, never silently repair an already running scientific run.

## P1: provenance is incomplete across reconstruction and audit

Training checks all engine source hashes and records package Python hashes. Evaluation validates engine hashes, checkpoint solver/seed/configuration, Anderson settings, and hashes of `run_docking.py` and `sequential_newton.py`. These are valuable checks. However it does not validate a new precision helper unless explicitly added, does not record its own evaluation code hash in the result, and reads mutable `actor_kwargs.json` with no manifest binding. State-dict loading cannot detect changes to non-state attributes such as z_std, integration, or density settings.

Audit records hashes of files passed on its CLI but does not enforce consistency with the originating run, does not hash its own implementation or Newton implementation, and can combine a checkpoint with unrelated input-bank constructor metadata. The runner instructs use of the same capsule as checkpoint and inputs, but the code does not enforce or explicitly label deviations. `prepare_inputs.py` records engine/checkpoint identity but no runtime precision, package implementation identity, or effective actor verification. Reconstructed banks remain reconstructed, not historical replay.

Minimum changes: bind effective constructor metadata and requested numerical policy to each new run manifest/checkpoint args and capsule. Evaluation must validate them before loading/rolling out, hash its evaluator plus shared helper dependencies, and report training and evaluation runtime policy separately. Audit must record all execution source hashes and enforce same-capsule identity in the campaign path, or explicitly expose a separate cross-checkpoint mode with both identities. Validate actual reconstruction properties against recorded metadata. Hash the frozen new source manifest and keep a documented original-to-new diff. Updating expected hashes without reviewed differences is not validation.

## P1: convergence and cap telemetry remain semantically asymmetric

`anderson_status` correctly separates native batch-mean convergence, reaching the iteration limit, and exhausting it without convergence. The existing last-iteration convergence test is appropriate.

Newton `cap_hit` means iterations >= cap, including convergence on the last iteration. This is correct as a limit-reached flag but not as a failure flag. In `Recorder`, `unconverged_budget_calls` defaults to false for every Newton call because Newton native metadata does not supply that key. Thus a Newton status-1 exhaustion contributes zero to this aggregate. `mean_converged_calls` also stays zero for Newton and must not be interpreted as a comparable convergence count.

Keep raw per-step status, iterations, and cap_hit unchanged. Add Newton-specific aggregates derived from statuses: converged-local/sample counts, status-1 budget exhaustion, line-search failure, singular/nonfinite/non-descent outcomes, and calls containing each outcome. Count cap reached independently. Label Anderson native-mean convergence separately from Newton local convergence and common residual failure. Preserve denominators (calls, samples, local steps and role). A line-search failure on iteration 25 is not the same as status-1 budget exhaustion.

The raw data demonstrate why both native and common residual checks are needed. GPU pilot strict FP32 reports all 4096 native local statuses converged but one sample fails the flattened full-batch recomputation. This is not evidence that the code lost a status. The solver evaluates varying active row subsets while telemetry evaluates B*T rows. Even strict FP32 can have small shape-dependent floating-point differences near the acceptance boundary. Keep both measurements with explicit evaluation shapes and policy. Do not silently relax tolerances or recategorize all native successes as certified full-batch residual successes.

## Dispatch, reconstruction, backward, and density findings

`make_actor` installs a temporary `engine.anderson` interception only around the native forward solve and restores it in `finally`, including exceptions. Newton returns detached roots, then the unchanged native method applies the existing g(q) attachment and shifted dense adjoint. The exact-backward guard prevents a later native iterative backward from accidentally invoking the forward interception. The global interception is suitable for this single-threaded trainer but not a generally thread-safe actor API.

The deterministic `act` override routes through the selected solver. This is necessary because original deterministic `act` calls native Anderson directly. Stochastic forward/logprob follows the common native core. Evaluation reconstructs the instrumented actor using the run solver and settings. No evidence in the inspected current paths shows silent Newton-to-Anderson fallback.

Constructor inspection finds no current campaign mismatch: `GatedDockingActor` forces hidden_dim=256, cap=25, tol=1e-5, exact_backward=True. The instrumentation then overwrites cap/tol to the requested arm and its bound metadata records those effective values. Recorded reconstruction therefore represents effective state rather than the literal first constructor invocation. The hardcoded metadata duplicates launcher behavior and will become fragile if the launcher changes. Add tests against actual effective actor fields and network dimensions for all four arms, including the high/tight settings. Avoid claiming metadata is an independently verified runtime constructor today.

Native `_solve_zstar_with_implicit_grad` computes g at the solved point, evaluates its adjoint Jacobian at the attached point, and adds the existing 1e-6 diagonal shift. `audit.attach` reproduces that mixed-point convention. Native density/readout code is retained, including safeguards. Existing AST-extracted parity test checks native action/logp/parameter gradients on a small double-precision actor. That is useful but does not test `make_actor`, actual launcher reconstruction, stochastic/deterministic dispatch, CUDA precision, or real full-batch SAC critic gradients. Preserve this estimator intentionally, without calling it exact differentiation of the finite solver program.

## Required meaningful tests and restart gate

1. **Precision override regression:** start with high/TF32 enabled, enter the real training initialization path, and inspect settings at first actual actor/critic computation. All must be strict. Separately launch fresh evaluation/audit/preparation processes under deliberately contaminated incoming policy and verify the explicit policy and runtime output. Assert float32 scientific tensors and no accidental autocast. FP64 independent reference remains explicitly labeled.
2. **Dispatch and restoration:** test four arms through `make_actor`, fixed noise, stochastic action, deterministic action, logprob, and backward. Spy on solver calls. Newton must not call native forward Anderson. Native exact backward must remain in use. Force a solver exception and verify `engine.anderson` object identity is restored.
3. **Effective reconstruction parity:** save/load a representative checkpoint and constructor metadata for every arm. Check hidden dimensions, T/dt, integration, exact_backward, z_std, density parameters, tolerance/cap, and matching fixed-noise actions/logp/gradients under the same strict runtime policy. Reject altered precision/helper hashes and altered constructor metadata before rollout.
4. **Telemetry regression:** explicitly cover Newton convergence on the last allowed iteration, status-1 exhaustion, line-search failure before/at cap, early-step failure followed by later success, and independently recomputed residual failure. Verify counters with role-specific denominators and do not force native/common decisions to match.
5. **Frozen full-batch CUDA validation:** replay all three diagnosed capsules with the unchanged Newton implementation under declared strict FP32, retain full raw results and the row473 failure. Compare native and flattened residuals, actions, density, and common SAC gradient readout to FP64 where reference validity permits. Record invalid reference cases instead of omitting them. Add batch-shape/permutation comparisons on the actual field because existing algebraic tests do not exercise GEMM dispatch.
6. **Bounded fresh CUDA preflight:** preserve four-arm smoke and ordinary batch1024 timing pilots from the runner plan. Verify actual CUDA and strict flags inside runtime, evaluation reconstruction, finite losses/gradients, expected checkpoints, capsule metadata, and complete telemetry. Estimate throughput after learning_starts. Do not use old high/TF32 pilots as campaign-speed estimates. Runtime assertions and source validation must pass before any 200k queue starts.

The existing solver tests meaningfully cover affine roots, Armijo damping, failure isolation, detachment, counts, and FP32 support. Retain them. The claimed 16-pass baseline in RUNNER_PROMPT is stale once tests are added, so replace the hardcoded count with the actual reviewed validation result and require zero skipped native-source tests. Revise runner documentation to name the new strict snapshot and runtime policy. A successful bounded preflight supports the approved restart, not a promise that every future root solve converges. If later numerical failure exceeds the predefined reporting/stop policy, preserve artifacts and stop affected dependent work without changing precision or solver parameters mid-run.
