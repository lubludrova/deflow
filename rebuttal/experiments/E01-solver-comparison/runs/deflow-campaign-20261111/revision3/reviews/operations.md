# Astra operations review

Decision: **do not restart using revision2 unchanged**. Conditional approval of the revised plan requires implementation review and fresh strict-FP32 server evidence. This is a static review of the named local files and diagnostics, not a claim that server processes were inspected or stopped.

## P0 launch blockers

1. **Precision is neither enforced nor restored.** `common.env`, `validate_run`, `evaluate`, and preflight only establish CUDA/finite tensors. They do not establish the actual precision inside engine.main, whose old initialization enables TF32. Apply one explicit strict policy after conflicting initialization, record actual state, and restore/check it in evaluation and audit. A parent process setting does not establish child settings. Old preflight markers cannot authorize the new condition.
2. **No durable stop or safe lifecycle.** `sync_gate` and the preflight wait loop cannot observe a stop request. `execute` has no interruption cleanup, and coordinator exit can leave children running. Add a campaign-specific stop latch checked before all claims and during waits, and serialized per-GPU claims shared by preflight and campaign. Record PID, start ticks, boot identity, command and process group. Stop only proven owned identities. Freeze future launches before stopping current jobs, verify exits, preserve interrupted states and never automatically resume.
3. **Preflight success is not evidence-bound.** `main` trusts the existence of PREFLIGHT_DONE, and when DONE and FAILED coexist it never checks FAILED. Bind DONE to campaign ID, contract/source digests, actual precision and all expected successful artifacts. Any conflicting failure, unknown identity or incomplete gate blocks admission. Preflight futures currently continue queued work after another gate fails. A shared failure latch must prevent new dependent preflight work.
4. **Numerical preflight is missing.** Finite checkpoints and successful exit missed the actual pathology. Require fixed full-batch replay plus fresh pilot diagnostics with native statuses, fresh residuals and reference validity. Do not replace this with Newton's Anderson-specific zero counters. See revised plan for borderline and hard-row treatment.

## P1 operational correctness

- **Incomplete source pinning.** `contract_check` pins four launchers but omits sync_local.py and external launch/stop wrappers. `check_sources` trusts mutable baseline hash files without independently pinning those files. Pin the complete runtime/source manifest and authorization overlay, including precision helper and numerical gate. Record original baseline and exact new diff. Checks must run for preflight as well as scientific admission. A changed file blocks future work and is reported without modifying an active run.
- **Availability is not an exclusive claim.** Three nvidia-smi samples followed by Popen leave a race. Per-GPU flock spanning training/evaluation or each exclusively owned process closes races between managed coordinators/preflight. External processes remain a separately checked condition. Slot ownership and start errors must have durable outcomes. `identity(process.pid)` can fail for a fast-exiting child before EXIT is recorded.
- **Monitor failure does not immediately close admission.** `supervised_monitor` writes MONITOR_FAILED, while sync_gate may accept the still-fresh old heartbeat for 120 seconds. Check an explicit health/failure latch at every admission and after waits. Report runtime co-runners and low disk promptly and block future launches. Do not indiscriminately kill foreign processes or automatically terminate scientific runs on transient utilization changes.
- **Sync receipt overclaims verification.** Receipt lacks campaign/contract/index identity and may reuse old terminal IDs. Only selected .pt and a few markers are hashed, while evaluation.json, summary.json, manifests and selection can change or be absent. Bind receipt to a specific immutable index generation and hashes of required terminal artifacts. An EXIT=0 is not accepted evaluation. Verify evaluation count/seed/checkpoint/policy before including its attempt. Recheck stop/health/source after waiting for sync.
- **Final sync ordering is wrong.** `main` syncs before writing final report and CAMPAIGN_TERMINAL. Require a post-terminal verified receipt covering final report, all terminal statuses and required scientific artifacts before claiming locally mirrored completion. Keep sync alive until that receipt. Distinguish remote completion from local verification pending.
- **Metadata races.** `write` uses one shared .tmp name protected only by a process-local lock. sync_index and campaign can collide across processes. Use unique temp names and atomic replace. `report` snapshots state under a lock but serializes and publishes outside it, allowing a stale report to overwrite a newer one. Use one report writer or serialize snapshot-to-publish. Hash mutable live files only from a coherent snapshot, or retry mismatches without blessing them.
- **Restart is not recovery.** The coordinator recreates STATE=PLANNED and only later encounters existing attempt directories. Fail immediately on reused scientific attempt/run roots. Permit read-only recovery/reporting, not re-execution. Claims and failed launches must be visible even if Popen never succeeds.
- **Missing audit rows.** AUDITS begins empty and audit_seed breaks after one failure without marking remaining rows. Prepopulate all nine rows, preserve MISSING and FAILED, and mark subsequent affected rows BLOCKED. Always emit 12 run rows and nine audit rows. Do not label an eligible capsule from an incomplete A run as a completed 200k control.
- **Validation/reporting gaps.** Check actual device and policy for every production train/eval/audit, not only smoke log text. Validate finite evaluation metrics, solver identity, checkpoint provenance and required artifacts. Link source and checkpoint hashes in reports. Distinguish interrupted, failed, blocked, deferred, training-finished and evaluation-finished.
- **Capacity and ETA.** Keep 120-second compact sync. The historical 22-GiB cap is a declared constraint, not physical necessity after space was freed. Measure selected bytes and projected remote growth before committing. Do not silently broaden retention or delete artifacts. Present max of per-slot sequential queue estimates plus preflight/evaluation/audit/sync overhead, with late-cost uncertainty. The old TF32 pilots are not strict-FP32 estimates.

## Numerical evidence governing acceptance

Diagnostics show two Newton capsules native 1024/1024 convergence under strict FP32, with one fresh FP32 borderline residual in the pilot capsule and none in N1. Both pass FP64. The late A capsule retains one difficult row (473) in strict FP32 and FP64, with independent reference invalid and local condition number about 326. These are distinct phenomena. A blanket all-rows-pass rule would reject known legitimate evidence, while a generic allowed failure percentage could conceal recurrence. Pin and classify the known rows, preserve exact residuals and reference failures, and halt on unexplained new disagreement. No threshold changes, row removal, method changes or selection by favorable residual are authorized.

## Minimal implementation scope

Use small shared policy/provenance checks, one explicit admission predicate, durable stop/health markers, per-GPU locks, atomic unique-temp writes, coherent sync receipts and complete status initialization. No scheduler framework, algorithm optimization, new seeds or revised scientific stopping rules are needed. Local verification should exercise conflicting preflight markers, precision restoration, stale/wrong-campaign receipts, final sync acknowledgment, fast child failure, stop while waiting, and all-nine audit failure accounting without launching training.
